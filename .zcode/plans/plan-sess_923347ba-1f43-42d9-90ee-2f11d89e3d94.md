# Solitaire: drag & drop, auto-foundations, solvability solver

## Context

Both card games (Klondike, FreeCell) share one server-authoritative engine (`src/server/solitaire.ts`); the client is a click-to-select renderer that sends `{t:'solitaire', action:'move', card, to}` messages. Today there is no dragging, no auto-play, and no way to know if a position is still winnable. The user wants: (1) full drag & drop of cards/runs, (2) cards auto-playing to foundations when safe — in **both** variants (FreeCell and Klondike), using the standard *safe* rule, (3) a live "Solvable / Stuck / Checking…" pill driven by a solver, for both games.

Two enablers fall out of the architecture:
- The public snapshot hides the stock and face-down cards (`-1` placeholders). A Klondike solver (and exact client-side drop validation) needs real state — this is a co-op shared table, so we simply reveal it.
- Client and server must agree on move legality and on the forced safe-autoplay sweep, or the solver's verdict won't match the game as played. So the pure engine moves to `src/shared/` and is reused everywhere.

## 1. Shared engine refactor

**New `src/shared/solitaire.ts`** — move verbatim from `src/server/solitaire.ts`: `SolitaireState`, `CardLocation`, `topCard`, `isDescendingAlternating`, `locateCard`, `movingCards`, `freeCellCapacity`, `canPlace`, `removeCards`, `appendCards`, `playMove`, `canAutoMove`, `autoMove`, `drawStock`, `recycleWaste`, `solitaireWon`, `foundationTotal`.

Add:
- `isSafeAutoMove(state, card): boolean` — standard safe rule: rank ≤ 2 always safe; otherwise both opposite-color foundation ranks ≥ r−1 **and** the other same-color foundation rank ≥ r−2 (foundation rank = top card rank or 0).
- `autoPlaySafe(state): boolean` — fixpoint sweep: while any top card (tableau tops, free cells, waste top) is a single-card legal foundation move **and** `isSafeAutoMove`, play it. Returns whether anything moved.

**`src/server/solitaire.ts`** keeps only `shuffledDeck` / `dealKlondike` / `dealFreeCell` / `dealSolitaire` (RNG-dependent, stays server-side) and re-exports everything from shared so existing imports/tests keep working.

## 2. Reveal full state to clients

- `src/shared/types.ts` — `PublicSolitaire.stock: number[]` (full order); `tableau` now carries real card values (no `-1`); keep `stockCount` and `faceDown` (rendering still needs the face-down counts).
- `src/server/room.ts` `toPublic()` (~line 280): send `stock: [...state.stock]`, drop the `-1` mapping.

## 3. Auto-play sweep on the server (both variants)

In `handleSolitaireAction` (`src/server/room.ts:1064`), after any applied action: `autoPlaySafe(solitaire.state)` before the `solitaireWon` check (covers move, draw, recycle, auto). Sweep moves don't count toward `moves`/player stats. Double-tap `auto` stays as the manual "send this card up now" escape hatch.

## 4. Drag & drop — `src/client/components/SolitaireBoard.tsx`

Pointer-event drag, complementing (not replacing) the existing click/double-click/keyboard flow:

- Small client helper (in the solver file or `src/client/lib/solitaireView.ts`) builds a real `SolitaireState` view from `PublicSolitaire` — then pickup (`movingCards`) and drop (`canPlace`) validation reuse the shared engine, guaranteeing client/server agreement.
- `onPointerDown` on movable cards (tableau face-up runs, waste top, free-cell cards, foundation top): determine pickup via `movingCards`; `setPointerCapture`; drag becomes visible after a ~5px threshold so clicks/dblclicks are unaffected (suppress the trailing click with a ref when a drag did happen).
- Ghost: a `createPortal`-to-body fixed-position stack of the dragged cards (reuse card face markup; fan step ≈ the column overlap `calc(var(--card-w) * 0.5)`, compressed for long runs), `pointer-events: none`. Source cards get `visibility: hidden` via a `solitaire-card-dragging` class.
- Drop targets: add `data-drop="tableau:i | foundation:i | freecell:i"` to `.solitaire-column`, `.solitaire-foundation`, `.solitaire-freecell` wrappers. On move/up, hit-test with `document.elementFromPoint(x,y).closest('[data-drop]')`; show an accent ring (`solitaire-drop-ok`) on the hovered target **only when `canPlace` says valid**.
- On valid drop: `onMove(card, target)` (server stays authoritative; local validation is exact since it's the same code + full state). Invalid → snap back, nothing sent. Re-validate pickup at pointerup against the latest snapshot (other players share the table).
- `pointercancel` / disabled / lost-validity → abort silently. Starting a drag clears the current selection. `touch-action: none` on `.solitaire-card` so touch drags work (board scroll stays available on empty areas).

## 5. Solver — live pill

- **`src/client/lib/solitaireSolver.ts`** (pure, node-testable): `solve(state, { budgetMs }) → 'solvable' | 'unsolvable' | 'unknown'`. DFS with a transposition Set, per-node normalization = apply `autoPlaySafe` fixpoint (models the real game exactly), foundation moves ordered first, then waste/column reveals, then free-cell parking. Macro-moves (supermoves incl. `freeCellCapacity`) for freecell; draw-1/draw-3 draw + recycle modeled for Klondike. Basic pruning: pointless whole-column shifts, inverse-of-previous-move. Budget ~5s; on exhaustion return `'unknown'`.
- **`src/client/lib/solitaireSolver.worker.ts`**: thin worker (spawned via Vite `?worker` import; type `self` locally with a minimal cast — tsconfig has no WebWorker lib). Terminate-and-respawn when a newer request supersedes a running one.
- **`src/client/components/SolitaireGame.tsx`**: debounce ~400ms after each snapshot change → solve → sidebar stats get a third cell **Solver** using `StatusPill` (`success` "Solvable", `live`/red "Stuck", neutral "Checking…"/"Unsure"). Hidden when the round isn't playing.
- Help text in the sidebar updated minimally (drag wording + "Safe cards climb to the foundations on their own.").

## 6. Styles — `src/client/styles.css`

Follow the existing light-first minimal language: `solitaire-card-dragging`, `solitaire-drag-ghost` (soft shadow, no pointer events), `solitaire-drop-ok` (accent ring consistent with `solitaire-card-selected`), `touch-action`, solver stat cell.
